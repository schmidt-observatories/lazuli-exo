## Bottom line

The code is small (about 2,000 lines of runtime), readable, numpy-only at import, and well tested. The parametric model is a real step up: it is validated against POSEIDON for 14 planets x 5 scenarios, it fixed the Vega/AB magnitude bug, and it defines the P_ref problem away for the custom-planet path.

**The main problem now is that the tool has two model paths that disagree with each other.** For the same planet and scenario, the showcase tables (`observe`) and the parametric path (`simulate` with `presets.showcase`) differ by 5–50 % in feature amplitude and by the same factor in template S/N (TRAPPIST-1 e cloudy: 4x). Both paths use the same noise, so this is purely the model convention: the tables put the archive radius at 10 bar (audit finding #3) and clamp the three cold planets' scale height to 300 K; the parametric path puts the archive radius at the transit photosphere and uses the true T_eq. The parametric convention is the physically right one for an archive transit radius. A user who flips between the Showcase and Custom tabs in the web UI sees this directly.

Why they differ (both effects are conventions, not bugs in either path):

- **Reference radius.** `precompute/scenarios.py` sets `P_REF_BAR = 10.0` and `make_model_tables.py` puts the archive `R_p` there. The transit photosphere then sits 3–10 scale heights above `R_p`, at a radius where g is lower and H larger, so the table planet is puffier than the archive planet. The parametric path puts the band-median transit radius at `R_p` and evaluates g there. An archive `pl_radj` is a transit radius, so the parametric convention is the right one. The table's median depth exceeds the archive `(R_p/R_s)^2` by 1–29 % (clear) and up to 57 % (TRAPPIST-1 e cloudy), as the 2026-09-26 audit found; nothing has changed on the table side.
- **Cold-planet temperature.** POSEIDON's single isotherm forces the fastchem 300 K floor onto the scale height for K2-18 b (284 K), LHS 1140 b (226 K) and TRAPPIST-1 e (250 K). The parametric path clamps the chemistry only and uses the true T_eq for H. That alone is a factor 0.75–0.95 on amplitude, on top of the radius effect.
- The deck scenarios diverge most because a deck removes the deep continuum and leaves only the line cores poking above it, and the number of scale heights between the deck and the cores is exactly what the radius convention changes.

`validate_zeta_grid.py` passes because it deliberately feeds the model each table's own band-median radius (and 300 K for the cold planets). That is the right way to test the model; it is not evidence that the two user-facing paths agree.

**Fix options, cheapest first.**

1. *Serve the showcase planets through the parametric model.* `observe(planet, scenario)` becomes `transmission_depth(**presets.showcase(planet, scenario))` plus the existing per-planet noise table. One model, one convention, the 14 MB of `models/*.npz` leave the runtime (keep them in `precompute/` as validation data; `validate_zeta_grid.py` and notebook 06 keep working). Cost: showcase spectra are then within 10–20 % of POSEIDON in amplitude (the validation tolerance) rather than being POSEIDON itself. Given that the POSEIDON tables are at the wrong radius by up to 10 H, this loses no real accuracy. The `flat` scenario is already parametric (`log_P_cloud_bar=-8`).
2. *Regenerate the tables on the parametric convention.* For each planet and scenario, run the parametric model once to get `zeta_ref`, set `P_ref = exp(-zeta_ref)` bar in `make_model_tables.py` so POSEIDON's `R(P_ref)` is the band-median radius to first order, and iterate once. This keeps POSEIDON as the showcase model but cannot fix the cold-planet temperature (POSEIDON's isotherm sets both chemistry and hydrostatics) and needs the poseidon env and a 1–2 h regeneration for every future change.
3. *Post-process the tables at load time* (shift the radius so the band-median matches the archive radius). Fixes the offset column above but not the amplitude ratio, because g and H at the photosphere stay those of the puffier planet. Not recommended.

Option 1 is what a lazy senior developer would do. It also retires #3 as a code issue and simplifies `observe`, `tables`, `webapp` and the docs.

### 5. [P1] Resolution (unchanged from #5)

The noise tables sample at R ~ 363 (525 channels over 0.40–1.70 um). `observe` raises for R >= 300 because a constant-R bin falls between two noise channels; the Flask UI allows R up to 500 and shows the resulting 400 error. Lazuli's own R_instr is 100–370 across the band (audit #5), so the honest cap is R_instr(lambda), not the sampling. Binning is still an unweighted mean with no LSF.

### 6. [P1] Bright hosts and ramp accounting (#6)

HAT-P-11 b is now desaturated at (2,1,0) after the Vega/AB fix. HD 189733 b (1540 px) and HD 209458 b (784 px) are still saturated at the floor and correctly flagged. On timing: slicersim's `integration_time = (n-1)(m+d) tframe` and `observing_time = nframes tframe x nramps`, and `depth_error` scales S/N by `sqrt(t14 / observing_time)`, so the first group's lost photons are accounted for. The reset between ramps is not modelled anywhere; if it costs one frame, the (2,1,0) hosts lose a further 33 % of wall time (sqrt(1.5) on their errors) and the (4,8,0) hosts 3 %. Worth a line in the caveats, and a `nreset_frames` knob once slicersim exposes it. The upstream saturation-criterion issue (charge at last read vs (n-1) groups) is unchanged.

### 7. [P2] Parametric-path polish (new, #14)

- `observe()` emits a `UserWarning` when the noise table has residual saturation; `simulate()` does not, although its `info["fully_desaturated"]` can be False (HD 189733 b: 1540 px). Library users of `simulate` get no signal; only `report.summary` adds a caveat.
- `transmission_depth` clamps T_eq to the grid *ceiling* (3000 K) as well as the floor, sets `T_clamped=True`, and `report.derived_rows` prints "clamped to grid floor; H uses T_eq". `forms` allows T_eq up to 4000 K, so this path is reachable from the UI. Say "grid edge" or report the direction.
- `forms._number` casts `int(float(raw))`, so `n_transits=2.5` becomes 2 with no warning (the audit's #9 item, now in the shared forms layer).
- `/api/simulate` only translates `ValueError` into a JSON 400. Without slicersim installed, the `ImportError` becomes an HTML 500. Translate `ImportError` to a clear 503-style message, since the README advertises the demo without slicersim.
- README/MODEL.md say "photon + read noise only". slicersim's variance includes dark current, ROIC glow, thermal dark, read noise, zodi background and the thermal cube. "Statistical noise only (photon, read, dark, zodi) with no systematics floor" is the accurate line.
- `webapp.app._derived` recomputes g, H and a linear `2 H R_p / R_s^2` amplitude with mu = 2.3 for the Showcase tab, while the Custom tab shows the parametric path's values. Use `atmosphere.transmission_depth`'s `info` for both (this falls out of fix option 1).

### 8. [P2] Live simulate performance (new, #15)

Measured today: WASP-39 b 6.1 s, HD 189733 b 1.3 s, TRAPPIST-1 e 0.4 s per `simulate()` call. The cost is `LazuliTarget` construction plus up to five `get_snr()` evaluations in `_desaturate`. The result depends only on `(teff, logg, feh, mag, band, mag_system, t14, instrument)`, not on the atmosphere knobs, so an `lru_cache` on `depth_error` (or on the PHOENIX-SED + slicersim stage) makes atmosphere sweeps free. The Django page will need this; the Flask demo does not.

## Code review notes

Things that are good and should stay:

- `import lazuli_exo` is numpy-only and a test enforces it in a fresh process.
- `atmosphere.transmission_depth` is a clean 90-line function with the physics in the docstring, exact hydrostatic mapping, the Ein deck operator, range checks that raise, and an `info` dict that reports every clamp and fallback.
- `slicer.depth_error` owns the Vega/AB conversion and the desaturation loop, and the precompute script is a thin loop over it, so the live path and the tables cannot drift.
- `forms` and `report` are shared by the Flask demo and the planned Django page; `tests/test_forms.py` pins the JSON keys.
- The table layer validates a schema version and gives actionable error messages naming the script to re-run.
- Test suite: 148 tests, analytic fixtures for the zeta and PHOENIX grids, a real-slicersim canary, and an end-to-end pass over the committed tables.

Smaller code points (none blocking):

- `webapp/app.py` duplicates `report.CAVEATS` as string literals and reimplements `_derived`; delete both and use `report`.
- `tables.load_star` bypasses the index name resolution that `load_model`/`load_noise` use (audit #9).
- `observe(R=0)` raises `ZeroDivisionError` from `constant_R_edges`; `observe(n_transits=2.5)` is accepted and reports `n_transits=2` while scaling errors by 1/sqrt(2.5) (audit #9, still true).
- `lightcurve._resolve_geometry` keys on `obs.planet`, so a `simulate()` run named after a registry planet gets that planet's geometry and LD even if the user changed its radius. Reasonable, but undocumented.
- `_desaturate` halves `n` then `m`; it never tries intermediate ramps, so the chosen readout is conservative rather than optimal. Fine for now; note it.
- `precompute/make_zeta_grid.py` writes `R_model: 9999` into meta because of `round(1/ln(wl[1]/wl[0]))`; cosmetic.
- Stale `__pycache__` entries still carry the old `GIT/terminator/` path, which is why pytest warnings print that path. Harmless; `find . -name __pycache__ -exec rm -r {} +` clears it.

Security: query parameters are parsed and clamped by `forms`; user strings are rendered with `textContent`, and the only `innerHTML` sinks receive server-generated strings. No injection path found in the demo.
