Tables and targets
==================

Everything the runtime computes comes from a small directory of ``.npz``
lookup tables plus a frozen target registry — about 50 MB in total (including
the parametric ζ and PHOENIX grids), committed to the repository at
``src/lazuli_exo/data/tables/`` and shipped as package data.

Layout
------

.. code-block:: text

   index.json                              # version, planets, scenarios
   models/<planet-slug>__<scenario>.npz    # wavelength_um, transit_depth, meta
   star/<planet-slug>.npz                  # wavelength_um, f_lambda, meta
   noise/<planet-slug>.npz                 # wavelength_um, depth_err_1transit, meta
   ld/<planet-slug>.npz                    # wavelength_um, u1, u2, meta

All wavelengths are in micron. ``meta`` is a JSON dict stored as a string
array, and every table has one — it is where the provenance and the caveat
flags live.

Slugs come from :func:`~lazuli_exo.tables.slugify`: lowercased, with runs of
non-alphanumeric characters collapsed to ``-`` (``"WASP-39 b"`` →
``wasp-39-b``).

The index
---------

``index.json`` is the catalogue: a schema ``version`` plus, per planet, its
slug, available scenarios, and whether noise and limb-darkening tables exist.

.. code-block:: python

   from lazuli_exo import tables

   tdir = tables.resolve_tables_dir(None)
   index = tables.load_index(tdir)
   index["planets"]["WASP-39 b"]
   # {'has_ld': True, 'has_noise': True, 'slug': 'wasp-39-b',
   #  'scenarios': ['clear', 'cloudy', 'flat', 'hazy', 'high_metallicity']}

:func:`~lazuli_exo.tables.load_index` **refuses a schema version mismatch**
with a clear error rather than misreading tables. The index is regenerated
from what is actually on disk by :func:`~lazuli_exo.tables.rebuild_index`,
which every precompute script calls when it finishes — so the catalogue cannot
drift from the files.

Resolving the tables directory
------------------------------

:func:`~lazuli_exo.tables.resolve_tables_dir` checks three sources, in order:

1. an explicit ``tables_dir=`` argument (also accepted by ``observe()``),
2. the ``LAZULI_EXO_TABLES`` environment variable,
3. the ``data/tables/`` directory inside the installed package.

.. note::

   Step 3 works for editable installs, repository checkouts, SHA-pinned VCS
   installs and built wheels alike, because the tables are declared as
   package data in ``pyproject.toml``. ``LAZULI_EXO_TABLES`` is only needed
   when a deployment wants the tables somewhere else.

Loading tables
--------------

Four loaders, each returning its arrays followed by ``meta``:

.. code-block:: python

   wl, depth, meta = tables.load_model(tdir, "WASP-39 b", "clear")
   wl, f_lambda, meta = tables.load_star(tdir, "WASP-39 b")
   wl, sigma_1transit, meta = tables.load_noise(tdir, "WASP-39 b")
   wl, u1, u2, meta = tables.load_ld(tdir, "WASP-39 b")

Planet names are matched against both the display name and the slug. Unknown
planets and unknown scenarios raise ``KeyError`` listing what *is* available;
an indexed-but-missing file raises ``FileNotFoundError`` naming the precompute
script to re-run.

The target registry
-------------------

:mod:`lazuli_exo.targets` is a frozen snapshot of the NASA Exoplanet Archive
``PSCompPars`` table (plus a small set of overrides), generated by
``precompute/freeze_targets.py``. It is a plain dict — no network access at
runtime, and no dependency on the archive being reachable or unchanged.

.. code-block:: python

   from lazuli_exo.targets import get_target

   get_target("WASP-39 b")
   # {'name': 'WASP-39 b', 'slug': 'wasp-39-b', 'period_d': 4.0552941,
   #  'a_over_rs': 11.39, 'inc_deg': 87.32, 'ecc': 0.0, 'w_deg': 90.0,
   #  't14_s': 10091.52, 'depth': 0.02122849, 'T_eq_K': 1166.0,
   #  'T_eff_K': 5485.0, 'J_mag': 10.663, 'provenance': 'NEA PSCompPars', ...}

The registry feeds the light-curve geometry (see :doc:`lightcurves`); a planet
missing from it, or missing ``a_over_rs`` / ``inc_deg`` / ``period_d``, falls
back to the trapezoid model.

.. warning::

   ``src/lazuli_exo/targets.py`` is **generated**. Do not edit it by hand —
   re-run ``precompute/freeze_targets.py`` to refresh it.

Regenerating the tables
-----------------------

Four steps, in two conda environments, because POSEIDON and slicersim never
need to be installed together:

.. code-block:: bash

   # 1. model + star tables (poseidon env; needs the opacity/chemistry inputs)
   POSEIDON_input_data=$HOME/inputs/ PYSYN_CDBS=$HOME/inputs/stellar_grids \
     ~/anaconda3/envs/poseidon/bin/python precompute/make_model_tables.py [planet ...]

   # 2. flat (featureless) baseline tables (analytic, py313 env)
   ~/anaconda3/envs/py313/bin/python precompute/make_flat_tables.py

   # 3. noise tables (py313 env; needs slicersim)
   ~/anaconda3/envs/py313/bin/python precompute/make_noise_tables.py

   # 4. limb-darkening tables (py313 env; needs exotic-ld, network on first
   #    run; PHOENIX files cache to $EXOTIC_LD_DATA, default
   #    ~/inputs/exotic_ld_data)
   ~/anaconda3/envs/py313/bin/python precompute/make_ld_tables.py

Each script calls ``tables.rebuild_index()`` when it finishes, so
``index.json`` always reflects what is actually on disk.

Caveat flags recorded in the data
---------------------------------

Two of the known approximations are flagged per table, so code can branch on
them:

.. list-table::
   :header-rows: 1
   :widths: 34 66

   * - Flag
     - Meaning
   * - ``meta["model"]["T_clamped"]``
     - The target's :math:`T_\mathrm{eq}` fell below the 300 K fastchem grid
       floor and was clamped. True for K2-18 b, LHS 1140 b, TRAPPIST-1 e.
   * - ``meta["noise"]["fully_desaturated"]``
     - ``False`` when the detector ramp retained saturated pixels; the count
       is in ``nsaturated_detpx``. ``observe()`` also raises a
       ``UserWarning``. See :doc:`noise`.
